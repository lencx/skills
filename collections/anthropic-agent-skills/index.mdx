<div class="curated-story">
<div class="curated-story__lede">
<p class="curated-story__thesis">This is not a software-delivery operating system. Its value is showing, in first-party files, how a Skill is packaged, progressively loaded, and tested against a baseline.</p>
<p>Each Skill is an independently loadable directory. Its name and description stay visible for discovery, SKILL.md loads when triggered, and scripts, references, or assets are used only when needed. The bundled skill-creator then evaluates real prompts against a baseline, grades assertions and output quality, and iterates from human feedback.</p>
</div>
<section class="curated-story__section curated-story__signature" aria-labelledby="signature-model">
<header class="curated-story__section-heading">
<h2 id="signature-model">What enters context, and when</h2>
<p>The package shape is a context-budget contract. A useful Skill keeps discovery cheap, delays its procedure until it triggers, and defers heavy material until the task actually needs it.</p>
</header>
<div class="curated-signature curated-signature--layers" data-story-kind="layers">
<article class="curated-signature__item" style="--story-index:1"><span class="curated-signature__meta">Always visible</span><h3>name + description</h3><p>Discovery metadata tells the model both what the Skill does and when it should be selected.</p></article><article class="curated-signature__item" style="--story-index:2"><span class="curated-signature__meta">After trigger</span><h3>SKILL.md</h3><p>The decision procedure enters context only after the trigger has matched.</p></article><article class="curated-signature__item" style="--story-index:3"><span class="curated-signature__meta">On demand</span><h3>scripts / references / assets</h3><p>Deterministic work, optional knowledge, and output material remain outside the main prompt until referenced or executed.</p></article>
</div>

<section class="curated-story__section" aria-labelledby="project-mechanisms">
<h2 id="project-mechanisms">What the repository teaches about Skill design</h2>
<div class="curated-story__mechanisms">
<article><h3>Three context levels</h3><p>Discovery metadata is always visible, SKILL.md loads only after a trigger, and bundled resources enter context or execute only when needed.</p></article><article><h3>Behavior is evaluated against a baseline</h3><p>skill-creator runs realistic prompts with and without the Skill, grades assertions and outputs, records cost and timing, and presents human review.</p></article><article><h3>Minimal and production-heavy examples</h3><p>A tiny template sits beside script- and asset-heavy document workflows used by Claude, exposing both packaging extremes and their license boundary.</p></article>
</div>
</section>
<section class="curated-story__section" aria-labelledby="project-practice">
<h2 id="project-practice">Evaluate behavior before polishing prose</h2>
<ol class="curated-story__practice">
<li><p>Start with the template and make the description say both what the skill does and when it should trigger.</p></li><li><p>Keep the main procedure in SKILL.md; move repeatable operations, optional knowledge, and output material into scripts, references, and assets.</p></li><li><p>Diagnose trigger failures separately from output failures: tune description with trigger evals, and tune the body with task assertions and human review.</p></li>
</ol>
</section>
<section class="curated-story__section" aria-labelledby="adoption-decision">
<h2 id="adoption-decision">Use it as a reference library, not a process owner</h2>
<div class="curated-story__decision">
<div>
<h3>Useful when</h3>
<p>Learning Agent Skill anatomy, creating a new Claude skill, or studying mature document and workflow examples.</p>
</div>
<div>
<h3>Do not assume</h3>
<p>Anthropic describes most entries as demonstration and educational material. Test them in your own environment; some document skills are source-available rather than open source.</p>
</div>
