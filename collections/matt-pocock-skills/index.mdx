<div class="curated-story">
<div class="curated-story__lede">
<p class="curated-story__thesis">This collection deliberately refuses to become one universal lifecycle. Explicit orchestrators compose work; automatically selected Skills contribute one engineering discipline; repository setup keeps both aligned with local conventions.</p>
<p>User-invoked Skills such as grill-with-docs and implement orchestrate a flow; model-invoked Skills such as diagnosis, TDD, research, and code review contribute one reusable discipline. A repository setup step first records the issue tracker, triage labels, and domain-context or ADR locations that later workflows must follow.</p>
</div>
<section class="curated-story__section curated-story__signature" aria-labelledby="signature-model">
<header class="curated-story__section-heading">
<h2 id="signature-model">Three responsibilities that must not blur together</h2>
<p>The most important design choice is the invocation boundary. It prevents an automatically triggered helper from silently taking over an entire engineering process.</p>
</header>
<div class="curated-signature curated-signature--roles" data-story-kind="roles">
<article class="curated-signature__item" style="--story-index:1"><span class="curated-signature__meta">User-invoked</span><h3>Orchestrators</h3><p>grill-with-docs, to-spec, and implement own an explicit flow requested by the user.</p></article><article class="curated-signature__item" style="--story-index:2"><span class="curated-signature__meta">Model-invoked</span><h3>Disciplines</h3><p>Diagnosis, TDD, research, domain modeling, and review each supply one reusable method.</p></article><article class="curated-signature__item" style="--story-index:3"><span class="curated-signature__meta">Repository-owned</span><h3>Setup contracts</h3><p>Tracker choice, triage vocabulary, and CONTEXT.md or ADR locations are recorded before later workflows depend on them.</p></article>
</div>

<section class="curated-story__section" aria-labelledby="project-mechanisms">
<h2 id="project-mechanisms">Engineering ideas worth borrowing independently</h2>
<div class="curated-story__mechanisms">
<article><h3>Domain language becomes repository state</h3><p>grill-with-docs sharpens terms in CONTEXT.md and records consequential decisions in ADRs so later sessions share the codebase’s nouns.</p></article><article><h3>Diagnosis starts with a red-capable command</h3><p>The diagnosing Skill refuses to theorize until one unattended command reproduces the exact symptom, then minimizes it and tests falsifiable hypotheses.</p></article><article><h3>Architecture uses a precise module vocabulary</h3><p>codebase-design looks for deep modules—substantial behavior behind a small interface—at explicit, testable seams instead of proposing broad rewrites.</p></article>
</div>
</section>
<section class="curated-story__section" aria-labelledby="project-practice">
<h2 id="project-practice">Start with repository setup, then pick one discipline</h2>
<ol class="curated-story__practice">
<li><p>Choose either the managed Claude plugin or editable skills.sh installation; installing both duplicates the skills.</p></li><li><p>Run the repository setup once so issue tracking, labels, and domain-document locations are explicit.</p></li><li><p>For a difficult bug, make the exact symptom fail from one fast command before ranking three to five falsifiable hypotheses.</p></li>
</ol>
</section>
<section class="curated-story__section" aria-labelledby="adoption-decision">
<h2 id="adoption-decision">Choose modular control over a single lifecycle</h2>
<div class="curated-story__decision">
<div>
<h3>Strong fit for</h3>
<p>Repositories that need better specification, domain modeling, work breakdown, TDD, difficult bug diagnosis, or code review.</p>
</div>
<div>
<h3>Setup cost</h3>
<p>The engineering workflows expect repository-level setup. Without tracker, label, and documentation conventions, their defaults can drift from the project.</p>
</div>
