<div class="curated-story">
<div class="curated-story__lede">
<p class="curated-story__thesis">Installing Superpowers means accepting a development method with hard gates. Design approval, isolation, TDD, separate reviews, and fresh verification are requirements, not optional tips.</p>
<p>Brainstorming and human design approval are hard gates before planning or code. Implementation then moves into an isolated worktree, executes narrow plan tasks with TDD, separates implementer self-review from specification and quality review, and accepts a completion claim only after a freshly run proving command.</p>
</div>
<section class="curated-story__section curated-story__signature" aria-labelledby="signature-model">
<header class="curated-story__section-heading">
<h2 id="signature-model">The path a change must pass before completion</h2>
<p>The sequence matters because each gate creates evidence consumed by the next one. Skipping ahead is treated as a process failure, even when the change looks small.</p>
</header>
<div class="curated-signature curated-signature--hard-gates" data-story-kind="hard-gates">
<article class="curated-signature__item" style="--story-index:1"><h3>Brainstorm</h3><p>Clarify intent and compare approaches.</p></article><article class="curated-signature__item" style="--story-index:2"><h3>Approve design</h3><p>A human accepts the proposed behavior before planning.</p></article><article class="curated-signature__item" style="--story-index:3"><h3>Isolate</h3><p>Use a worktree and establish a clean baseline.</p></article><article class="curated-signature__item" style="--story-index:4"><h3>Plan</h3><p>Write narrow tasks with files and proof commands.</p></article><article class="curated-signature__item" style="--story-index:5"><h3>TDD</h3><p>Implement through red, green, and refactor.</p></article><article class="curated-signature__item" style="--story-index:6"><h3>Review twice</h3><p>Check specification first, then code quality.</p></article><article class="curated-signature__item" style="--story-index:7"><h3>Verify fresh</h3><p>Rerun the proving command immediately before the claim.</p></article>
</div>

<section class="curated-story__section" aria-labelledby="project-mechanisms">
<h2 id="project-mechanisms">Why these gates are load-bearing</h2>
<div class="curated-story__mechanisms">
<article><h3>Design approval is a hard gate</h3><p>Even small behavior changes resolve intent, alternatives, and a readable design before scaffolding, planning, or implementation begins.</p></article><article><h3>Implementation and review are distinct roles</h3><p>Each task is implemented, self-reviewed, checked for specification compliance, checked for code quality, and re-reviewed after fixes.</p></article><article><h3>Verification is temporally fresh</h3><p>A completion claim is invalid unless its proving command was rerun immediately and the complete output and exit status were read.</p></article>
</div>
</section>
<section class="curated-story__section" aria-labelledby="project-practice">
<h2 id="project-practice">Trial the method on one real change</h2>
<ol class="curated-story__practice">
<li><p>Complete brainstorming and design approval before asking the agent to write an implementation plan.</p></li><li><p>Reuse an existing isolated workspace when possible, then run setup and baseline tests before changing code.</p></li><li><p>Follow red, green, refactor and rerun the command that directly proves completion before making the claim.</p></li>
</ol>
</section>
<section class="curated-story__section" aria-labelledby="adoption-decision">
<h2 id="adoption-decision">Adopting it changes how work is approved</h2>
<div class="curated-story__decision">
<div>
<h3>Worth the overhead when</h3>
<p>Feature development or bug fixes that benefit from a rigorous specification, isolated implementation, TDD, subagent collaboration, and review loop.</p>
</div>
<div>
<h3>Process conflict</h3>
<p>Its repository describes the workflows as mandatory rather than optional suggestions. Confirm that this degree of process ownership fits the project’s existing rules.</p>
