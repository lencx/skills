<div class="curated-story">
<div class="curated-story__lede">
<p class="curated-story__thesis">这套集合刻意拒绝成为统一生命周期：显式 orchestrator 负责组合流程，自动选中的 Skill 只贡献一种工程纪律，而仓库 setup 让两者服从项目本身的约定。</p>
<p>grill-with-docs、implement 等用户调用 Skills 负责组织流程；诊断、TDD、research 和 code review 等模型调用 Skills 只提供一项可复用纪律。首次 setup 会先记录 issue tracker、triage 标签，以及领域上下文与 ADR 的位置，后续流程必须遵循这些仓库约定。</p>
</div>
<section class="curated-story__section curated-story__signature" aria-labelledby="signature-model">
<header class="curated-story__section-heading">
<h2 id="signature-model">三种不能混在一起的职责</h2>
<p>最重要的设计选择是调用边界。它防止一个自动触发的辅助 Skill 在不知不觉中接管整个工程流程。</p>
</header>
<div class="curated-signature curated-signature--roles" data-story-kind="roles">
<article class="curated-signature__item" style="--story-index:1"><span class="curated-signature__meta">用户显式调用</span><h3>流程编排器</h3><p>grill-with-docs、to-spec 与 implement 负责用户明确要求的一段流程。</p></article><article class="curated-signature__item" style="--story-index:2"><span class="curated-signature__meta">模型按需调用</span><h3>工程纪律</h3><p>诊断、TDD、research、领域建模与评审分别只提供一种可复用方法。</p></article><article class="curated-signature__item" style="--story-index:3"><span class="curated-signature__meta">仓库拥有</span><h3>Setup 契约</h3><p>后续流程开始依赖之前，先记录 tracker、triage 词汇，以及 CONTEXT.md 或 ADR 的位置。</p></article>
</div>

<section class="curated-story__section" aria-labelledby="project-mechanisms">
<h2 id="project-mechanisms">可以单独借鉴的工程机制</h2>
<div class="curated-story__mechanisms">
<article><h3>领域语言成为仓库状态</h3><p>grill-with-docs 会在 CONTEXT.md 中磨清术语，并把重要决策写入 ADR，让后续会话沿用代码库自己的名词。</p></article><article><h3>诊断从可变红的命令开始</h3><p>diagnosing Skill 在一个无人值守命令准确复现症状前拒绝推测，之后再最小化复现并检验可证伪假设。</p></article><article><h3>架构使用精确模块词汇</h3><p>codebase-design 在明确且可测试的 seam 上寻找深模块——用小接口隐藏大量行为，而不是泛泛建议重写。</p></article>
</div>
</section>
<section class="curated-story__section" aria-labelledby="project-practice">
<h2 id="project-practice">先完成仓库 Setup，再选择一种纪律</h2>
<ol class="curated-story__practice">
<li><p>托管的 Claude 插件和可编辑的 skills.sh 安装方式二选一，避免重复加载。</p></li><li><p>首次使用时完成仓库 setup，明确 issue tracker、标签和领域文档位置。</p></li><li><p>困难 Bug 先让一个快速命令稳定复现准确症状，再排列三到五个可证伪假设。</p></li>
</ol>
</section>
<section class="curated-story__section" aria-labelledby="adoption-decision">
<h2 id="adoption-decision">选择模块化控制，而不是统一生命周期</h2>
<div class="curated-story__decision">
<div>
<h3>适合</h3>
<p>需要更好规格、领域建模、任务拆分、TDD、困难问题诊断或代码评审的仓库。</p>
</div>
<div>
<h3>采用成本</h3>
<p>工程 Skills 假设已经完成仓库级 setup；缺少 tracker、标签与文档约定时，默认流程可能与项目错位。</p>
</div>
</div>
</section>
